## Encerramento no menu

O usuário confirmou que o clique manual no aviso de conexão perdida mudou o botão de “Fechar” para “Fechando...”, mas o Skyrim permaneceu aberto. Isso demonstra resposta da página ao clique, sem provar sozinho a entrega ao client.

`ServerDownService` e `AccessRevokedService` esperavam o evento `update` para processar a saída e chamavam `Debug.quitGame()`. O runtime liga esse evento ao update de gameplay/Papyrus. A correção processa o pedido no `tick`, também disponível no menu, e usa a API existente `win32.exitProcess()`. Apesar do nome, a implementação desta versão apenas marca `RE::Main::quitGame`, solicitando saída normal. O callback do navegador continua apenas enfileirando o pedido. A reconexão pendente também passa a ser processada no tick.

Quatro regressões verificam o processamento sem evento de gameplay, saída diferida, confirmação de acesso revogado e uma única tentativa de reconexão. As 19 verificações de client passaram; o bundle foi reconstruído com webpack. SHA256 do bundle instalado no mod de teste: `999D74232515982DA0A0C83F9D17F47EA619961D7E86A9E80475659D052D66D3`.

Às 26604 ms, chegaram os eventos de clique no botão e a mensagem `cef::serverDown:close`. ## Falha introduzida pelo diagnóstico

O diagnóstico local inicialmente usou `require('skyrimPlatform')`. No runtime embarcado deste snapshot, a API é injetada como global `skyrimPlatform`; não existe como pacote Node. O erro `Cannot find module 'skyrimPlatform'` interrompeu a inicialização na execução das 02:48. As DLLs e o DOM ainda inicializaram, mas isso não demonstra que o client iniciou.

O template foi corrigido para `globalThis.skyrimPlatform`, envolvido em uma função para não vazar declarações globais, e instalado com o jogo fechado. Um teste executa esse script em contexto compartilhado com a API global, rejeita qualquer tentativa de resolver a API como pacote Node e verifica callbacks de tick e browserMessage. As 20 verificações passaram após a correção. O próximo lançamento confirmou interface inicializada e ausência dessa exceção.

O diagnóstico é auxiliar local, não faz parte do overlay distribuído. Registra contagens de tick/update, estado do backend e tipos de evento/IDs permitidos dos botões; não registra texto digitado, credenciais ou dados do jogador. Os dados ficam em `local-artifacts`, ignorado pelo Git.

O usuário confirmou o mesmo resultado: abriu o SKSE, houve falha de conexão e, ao clicar em Fechar, o jogo encerrou. O teste foi realizado sem controle de mouse ou teclado pelo agente.
